# 时光回放小偷 · Loop Heist

回合制潜行解谜。你控制一名小偷潜入守卫巡逻的房间，每一步都会被录下来。结束一轮（轮回）后，这一轮的动作会变成幽灵，在之后的每一轮里逐步重放。你需要让多个幽灵互相配合，踩住压力板、拿到全部宝物，再抵达出口。

## 运行方式

- 直接双击 `index.html` 即可离线游玩（纯 `<script>` 普通脚本，无构建、无外部资源）。
- 或在仓库根目录执行 `python3 -m http.server 8080`，访问 `http://localhost:8080/loop-heist/`。

## 操作

| 操作 | 键盘 | 触屏 |
|---|---|---|
| 移动一格（一回合） | 方向键 / WASD | 方向键按钮 |
| 原地等待一回合 | 空格 | 中间圆点 |
| 轮回（录下当前尝试，留下幽灵，重新开始） | R | 轮回按钮 |
| 重来本关（清空幽灵） | X | 重来按钮 |
| 静音切换 | M | 声音按钮 |
| 返回选关 | Esc | 选关按钮 |

## 玩法规则

- 每次按键记为一个回合，玩家、幽灵与守卫同时行动。
- 守卫沿固定路线循环巡逻，朝向上一步的方向，向前看 4 格；视线被墙和关闭的门/闸门挡住。玩家或幽灵落入视野即触发警报。
- 警报后这一轮结束，但它的录像同样会变成幽灵。幽灵也会被守卫发现，所以失败的录像仍然有用，也可能成为新的麻烦。
- 压力板：有任意身体（玩家或幽灵）站在上面时，普通门（`D`）开启；总闸门（`G`）要求所有压力板同时被踩住。
- 宝物：任何身体经过即拾取，拾取状态在每一轮里从零重算。宝物全部拿到后，玩家站在出口上即通关。
- 幽灵数量有上限（默认 5 个）。达到上限后若再次被抓，本关失败，需要重来。

## 关卡

| # | 名称 | 教学重点 |
|---|---|---|
| 1 | 入门 | 移动、宝物与出口 |
| 2 | 压力板 | 幽灵踩板，门保持开启 |
| 3 | 巡逻者 | 守卫视野只朝前方，跟在背后 |
| 4 | 总闸门 | 所有压力板同时压住，需要两个幽灵 |
| 5 | 双线 | 幽灵踩板 + 玩家穿过守卫巡逻线 |

## 技术要点

- `js/sim.js`：纯逻辑内核，不依赖 DOM。同一份录像在任何时候重放结果一致，幽灵的行为可以提前规划。
- `js/render.js`：Canvas 2D 绘制，移动使用 140ms 插值动画，守卫视野以半透明红色格子显示。
- `js/audio.js`：Web Audio 程序化合成音效，AudioContext 在首次输入后解锁，不可用时静默降级。
- `js/main.js`：关卡选择、输入、轮回与失败判定、本地进度存档（键名 `loop_heist_progress_v1`，带版本号，读取时做类型与范围校验）。
- `js/levels.js`：关卡数据，字符地图加守卫路线，新增关卡只需追加一项。

## 测试

```bash
node loop-heist/test.js
```

覆盖两件事：

1. 规则断言：门/闸门的开启条件、守卫视野判定、幽灵被看见同样触发警报。
2. 关卡可解性：内置 BFS 求解器直接调用真实 `sim` 规则，逐关搜索通关动作序列；同时断言第二、四、五关在没有幽灵时无解，防止关卡设计被改坏。

## 已知限制

- 幽灵的录像一旦会撞进守卫视野，后续每一轮都会在同一个回合结束。这是有意的强约束，但新手容易困惑。
- 移动为回合制，没有连续移动手感，这是有意为之，便于规划幽灵路线。
- 关卡进度按索引存在本地，后续在中间插入关卡会让旧存档错位。
