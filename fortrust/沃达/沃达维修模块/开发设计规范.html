1. 业务架构与双入口体系

维修管理涉及整个机组全生命周期的故障排查、配件更换、照片归档和履历追溯。根据最新定稿需求，维修管理在 PC 端分为两个入口协同运作：

入口一：电站详情内「维修记录」Tab 电站维度 / 机组视角

位置：在电站详情（如利比亚106MW燃气电站）的二级 Tab 栏中，在「运行记录」之后、「预警记录」之前，新增 维修记录 Tab。

作用：按电站列出该电站下的所有机组列表（如 1~106 台机组依次排列），展示各机组的运行状态、维修状态、维修次数，并支持直接对某机组发起维修登记或查看该机组的历史维修记录。

入口二：运维管理菜单下「维修管理」 全平台全局维度 / 工单池视角

位置：主菜单 运维管理 ➔ 维修管理（组件路径：operation/repairManagement/index）。

作用：汇集全平台所有电站与机组的维修工单池，按状态页签（全部 / 待维修 / 维修中 / 已完成）进行多维组合筛选、批量导出、打印，并支持全局发起维修登记。

2. 状态机与三步流转机制

核心业务原则：维修登记不需要审核流程，由登记人员在登记界面手动登记推进三个阶段，系统自动更新并确认对应的维修状态。

1
维修登记 ➔ 待维修
创建维修登记单，选择电站/机组，关联报警记录或停机记录，录入故障基本信息与维修事项。
2
开始维修 ➔ 维修中
维修人员到达现场开展解体检修、更换配件、过程拍照，可多次保存草稿暂存记录。
3
完工确认 ➔ 已完成
试运行正常后，主维修人与协助人员分别进行电子手写签名，提交完工，工单归档并计入机组履历。
💡 与报警模块的联动：在「报警处理登记」页面中新增【保存并登记维修】按钮，点击后自动携带该报警的机组、故障级别、故障类型、过程描述跳转至维修登记页面；同时报警处理登记页面支持选择该机组历史维修记录反向带入。

完全与报警处理登记模块的数据字典拉齐：

3.1 故障级别字典 (Fault Level)

级别编码级别名称说明Tag 样式
1一级：报警停机类导致机组停机的重大紧急故障一级：报警停机类
2二级：报警故障类机组带故障运行，需紧急排查二级：报警故障类
3三级：一般警告类参数越限或一般异常警告三级：一般警告类

类型编码类型名称典型涉及部件
1电控系统类 (ECU)ECU、通信板卡、传感器通信、执行器驱动
2燃料与燃烧系统类燃油泵、喷油嘴、火花塞、燃气阀组、点火系统
3冷却与润滑系统类散热水箱、水泵、润滑油泵、机油滤清器、温控阀
4机械与结构类齿轮箱、轴承、曲轴、连杆、机体减震、底座
5控制与安全保护类急停回路、防爆阀、超速保护、逆功率保护
6环境与辅助系统类通风风机、机房温湿度、百叶窗、消音降噪
7发电侧系统类发电机定子/转子、AVR 励磁、高低压断路器、PT/CT
9其他类外观破损、风速仪、铭牌标识等

4. 数据结构与字段模型

4.1 维修工单主表 (`repair_order`)

字段名类型必填说明
idbigint是主键 ID
orderNovarchar(32)是工单编号（如 BX20260804001）
registerNovarchar(32)是维修登记编号（如 WXD20260805001，自动生成）

gensetId / gensetNamebigint / varchar是机组 ID 与名称
cloudCatCodevarchar(64)否云猫编号（机组选择后自动带出，如 YM-001-A）
runHoursvarchar(32)否机组运行时长（自动带出，如 12,580 h）
relatedAlarmDescvarchar(255)否关联报警记录（下拉选择带入）
relatedStopDescvarchar(255)否关联停机记录（下拉选择带入）
repairItemvarchar(200)是维修事项（如 更换火花塞、齿轮箱异响维修）
faultLeveltinyint是故障级别（1-一级 2-二级 3-三级 4-四级）
faultTypetinyint是故障类型（1-电控 2-燃料 3-冷却 4-机械 5-保护 6-环境 7-发电 9-其他）
repairStartTime / repairEndTimedatetime是维修开始时间 / 结束时间
repairHoursdecimal(5,1)是维修工时（根据起止时间自动计算，支持微调）
repairProcesstext是维修过程描述（≤1000字，支持时间分段）
repairResulttinyint是维修结果（1-已修复 2-更换配件修复 3-临时处理待观察 4-无法修复）
statustinyint是状态：0-待维修 1-维修中 2-已完成
remarkvarchar(500)否补充说明备注

quantityvarchar(32)数量（如 1、280）

4.3 作业人员与电子签名子表 (`repair_order_repairer`)
